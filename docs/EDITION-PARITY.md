## History hygiene

Commits before 1.1.5 contain the pre-redaction text (real place names). `private-rev2` must never be pushed. Publish by squashing onto `main`; the public history then contains one clean commit and none of the old strings. If the branch is ever pushed by accident, treat the strings as public and rotate anything sensitive that was in the same files.

Legend: `OK` = marker found; `MISSING` = file present, marker absent; `ABSENT` = we do not hold that file, so the rule cannot be judged; `UNVERIFIED` = some target files are absent.

## Sync procedure (manual, ~10 minutes)

1. Edit the workspace edition first; it is the source of truth.
2. Update the rule marker in `docs/rule-manifest.json` if the wording of a rule changed.
3. `python3 scripts/check_all.py` — workspace must be clean.
4. Regenerate the Project copies: rewrite `` `references/x.md` `` → `` `x.md` ``, drop workspace-only sections (`Runtime portability`), and replace "authorized workspace" with "Project" where it refers to storage.
5. Diff the regenerated files against `project-edition/` — every changed line must be intentional.
6. Upload to the Project, then re-download and diff once to prove the upload landed.
7. `git commit` with the rule IDs touched; add a CHANGELOG entry.

## When to stop doing this by hand

Build a generator when any two of these become true:

- more than one rule change per month;
- a third runtime appears (WorkBuddy, mobile, another agent);
- a regeneration step is skipped twice in a row;
- the Project file set changes shape (renames, splits).

Until then the manual procedure plus the checker is cheaper than a templating layer over seven Markdown files.
