# Experiment 2 — End-to-end workflow utility (draft, not executed)

**Question:** Does the PTI workflow help a user reach a trustworthy, shareable output with less total effort? This is NOT an isolated test of instruction quality.

1. Obtain consent and a previously unused completed-trip fact packet. Provide the same documents, available tools, model/version and resource budget to both arms. Keep personal records private.
2. Baseline: normal model with a high-quality request describing target quality, A4 output, no internal filenames and explicit facts/unknowns. PTI: same user objective and fact packet, with the PTI workflow available.
3. Log the steps and time from initial materials to the user's accepted DOCX/PDF; include setup time, tool failures, corrections, file maintenance and QA runs. Do not ignore installation overhead.
4. Verify artifacts independently: factual fidelity, missing Chinese and Latin text, A4 page size, any clipping and friends-edition readability. Obtain a blind reader preference with facts attached.
5. Record at least three independent runs per arm if using model-to-model comparisons. Do not compare a scripting-enabled PTI arm to a baseline prohibited from running the same QA tools without identifying that difference.
6. Summarize specific user benefits and costs, not statistically significant percentages. Distinguish results attributable to tools, instructions, personal data and persistence.
